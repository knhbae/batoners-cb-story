# 화면·기능 검증

검증일: 2026-11-23. 정적 사이트를 로컬 서버에서 실행하고 Playwright Chromium 159로 조작했습니다. 내장 브라우저와 JavaScript 실행 세션은 초기화 오류로 사용할 수 없어, 설치된 Playwright의 Chromium을 사용했습니다.

## 결과

- 8장 × 5개 화면 크기 = 40개 화면 상태 확인. 이미지·글꼴 로딩 성공, 가로 넘침 및 본문·주석 겹침 없음.
- 다음·이전·처음/마지막·연속 클릭, 화살표·Home/End, 목차 이동, 페이지별 주소·브라우저 뒤로가기 통과.
- 세금 예시 3개 및 앞뒤 장 선택 유지 통과. 165·264·385만원과 5.50·8.80·12.83% 확인.
- 목차·전체 설명 열기, 닫기 버튼·Escape, 포커스 복원, 모달 뒤쪽 페이지 이동 방지 통과.
- 실제 터치 입력을 에뮬레이션해 좌우 스와이프, 바로 뒤따르는 버튼 탭, 세로 스크롤 확인. 세로 스크롤은 장을 바꾸지 않음.
- 전체 설명의 6개 항목·4개 표, 독립 설명 페이지, 인쇄 스타일 및 JavaScript 비활성 상태의 설명 링크 확인.
- 동작 줄이기 설정에서 페이지 애니메이션 없음. 앱 실행 오류 및 내부 파일 HTTP 오류 없음.

화면 크기: 1440×1000, 1366×768, 768×1024, 390×844, 360×800.

실물 휴대폰, Safari, 보조기술 사용자의 실제 이용은 이번 검증에 포함하지 않았습니다. 모바일 검증은 Chromium의 터치·화면 크기 에뮬레이션입니다. 내용이 긴 장은 아래로 스크롤해 읽도록 설계했습니다.

## 발견 후 수정

1. 모바일 말풍선의 긴 문장이 인물 얼굴을 가렸습니다. 말풍선 폭·글자 크기·그림 위치를 조정했습니다.
2. 수평 스와이프 직후 첫 탭이 브라우저 동작에 흡수되는 경우를 재현했습니다. 수평 제스처에서만 기본 터치 이동을 막고, 터치 종료 후 페이지를 바꾸도록 수정했습니다. 이후 첫 탭과 세로 스크롤을 함께 재검증했습니다.

## 콘셉트 대비 화면 검토

초기 화면 콘셉트와 최종 브라우저 캡처를 함께 열어 비교했습니다. 1366px 화면의 중간 장과 마지막 장, 모바일 말풍선·본문·전체 설명도 별도로 확인했습니다.

| 비교 지점 | 실제 구현 및 판단 |
| --- | --- |
| 펼친 책 구성 | 데스크톱 그림/본문 1:1 구성과 가운데 접힘 유지. 모바일은 세로 배치로 의도적으로 변경 |
| 종이·잉크·강조색 | 따뜻한 바탕, 크림색 종이, 짙은 초록 글자, 주황 강조 유지 |
| 삽화 | 같은 세 인물, 복장, 색연필 질감 유지. 장마다 계약·계산·자문·일정 장면으로 교체 |
| 말풍선 | 이미지 글자를 재사용하지 않고 HTML로 구현. 작은 화면에서도 얼굴과 대사 구별 가능 |
| 제목·본문 | Gaegu 제목과 Pretendard 본문 사용. 생성 콘셉트의 글씨보다 본문은 규칙적인 서체로 구현 |
| 책 테두리 | 손그림 외곽선의 질감을 CSS 테두리·종이 겹침·그림자로 단순화한 의도적 차이 |
| 페이지 제어 | 8개 진행 막대·이전/다음 유지. 모바일에서는 하단에 고정하고 작은 화면의 본문은 스크롤 |
| 숫자·근거 | 원본 콘셉트에 없던 과세표준 선택과 전체 설명 모달을 같은 색·서체로 확장 |

중요한 시각적 미해결 사항 없음. 전체 설명은 만화보다 정보 밀도가 높으며, 표는 필요한 경우 표 영역 안에서 가로로 이동합니다.

## 재현

```text
npm install
npx playwright install chromium
npm start
```

다른 터미널에서 `npm run verify`를 실행합니다. 검증 결과와 캡처는 Git에 포함되지 않는 `output/local/`에 생성됩니다. `STORY_URL` 환경변수에 공개 사이트 주소를 넣으면 배포 주소를 대상으로 실행합니다.
